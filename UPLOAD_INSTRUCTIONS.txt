BOP.IN /HRMS DEPLOYMENT

Build the site from the project folder:

  npm run deploy:web

This creates bop-hrms-deploy.zip. Do not use the legacy dist.zip for cPanel
deployment, and do not move _expo or assets to public_html root.

UPLOAD STEPS

1. Back up the existing public_html/HRMS folder in cPanel.
2. Remove or rename the old public_html/HRMS folder so stale hashed bundles
   cannot remain mixed with the new release.
3. Upload bop-hrms-deploy.zip into public_html (not public_html/HRMS).
4. Extract the archive there. Its included HRMS folder must produce exactly:

   public_html/HRMS/index.html
   public_html/HRMS/.htaccess
   public_html/HRMS/_expo/
   public_html/HRMS/assets/
   public_html/HRMS/favicon.ico
   public_html/HRMS/manifest.webmanifest
   public_html/HRMS/sw.js

5. Confirm that public_html/_expo and public_html/assets are not being used by
   this HRMS deployment. Both asset folders belong inside HRMS.
6. Open https://bop.in/HRMS/ in an incognito window.
7. In DevTools > Application > Service Workers, unregister an older HRMS
   worker if the browser still shows a cached release, then reload once.

The three startup JavaScript URLs shown in index.html must return HTTP 200 from
https://bop.in/HRMS/_expo/static/js/web/. If any returns 404, the HRMS/_expo
folder was not extracted in the correct location or filename case was changed.
